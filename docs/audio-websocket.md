# 音频 WebSocket 协议 v1

控制台入口为 `ws://127.0.0.1:8080/api/audio/ws`。Docker 网络内可直连 `ws://controller:8080/ws`。通过 TLS 反向代理接入时使用 `wss://` 并转发 Upgrade。服务端接受无 Origin 的非浏览器客户端和同源浏览器客户端。客户端可在启动前连接，在 Stop、Restart、循环边界之后保持订阅。每个客户端收到相同会话的数据。

## 文本消息

| 类型 | 字段 | 时机 |
| --- | --- | --- |
| `hello` | `version: 1`、`state` | 每次连接的首条消息 |
| `start` | `session`、`format: "s16le"`、`sampleRate: 16000`、`channels: 1`、`frameMs: 20`、`frameBytes: 640` | 接下来将发送该会话的 PCM。中途订阅者也会先收到此消息 |
| `end` | `session`、`reason`、`error` | `reason` 为 `ended`、`stopped` 或 `error`，失败时 `error` 提供诊断 |

`session` 是 16 字节随机标识的 32 字符小写十六进制表示。Start 和 Restart 创建新会话。每次循环沿用同一会话。

## 二进制消息

每个消息为一个完整帧，共 672 字节。

| 字节偏移 | 内容 |
| --- | --- |
| 0–15 | 16 字节原始会话标识，按十六进制逐字节表示后与 `session` 一致 |
| 16–23 | 无符号 64 位小端序列号，从 0 开始 |
| 24–31 | 无符号 64 位小端会话媒体时间戳，单位毫秒，等于序列号乘以 20 |
| 32–671 | 320 个有符号 16 位小端采样，16 kHz 单声道 |

会话内以约每 20 ms 发送一帧。中途连接时首个序列号可能大于 0。循环边界可以位于帧内，序列号和 PTS 持续递增。非循环文件的尾帧补零至 640 字节。墙钟存在调度和网络抖动。读取失败或服务重启后，客户端可重新连接并等待新的 `start`。

每个客户端有 16 条消息的发送队列，超过队列容量或写入超时将断开该客户端。服务端每 10 秒发 Ping，客户端应回复 Pong。

```sh
node tools/audio-client.mjs ws://127.0.0.1:8080/api/audio/ws 100
```

测试客户端检查会话标识、消息大小、序列号、PTS 和平均到达间隔。短音频开启 Loop 后再运行。
